# Чек-лист сдачи шага

Пройди перед отчётом о готовности шага: после мержа тикетов и до ответа
пользователю. Каждый пункт проверяется командой или тестом, а не на глаз.

- [ ] Сквозной сценарий гостя целиком: выбор типа → календарь → запись на
      свободный слот → подтверждение. Проверка: e2e-сценарий бронирования.
- [ ] Одна команда запускает все проверки локально и в CI, включая браузерный
      слой. Проверка: `mise run check:all` и тот же вызов в workflow.
- [ ] Занятый слот не предлагается как свободный, повторная запись не проходит,
      в том числе для другого типа встречи. Проверка: API-тесты доступности и
      `SLOT_TAKEN` на общей оси.
- [ ] При конфликте слота гость видит понятное сообщение. Проверка: e2e на
      занятый слот и баннер в интерфейсе.
- [ ] Правила бронирования выполняются на сервере, а не только в интерфейсе.
      Проверка: API-тест на старт вне сетки, в выходной, в прошлом и за окном.
- [ ] Владелец видит предстоящие встречи всех типов. Проверка: тест списка с
      двумя типами и разными слотами.
- [ ] TypeSpec-контракт — источник истины; OpenAPI и клиентский SDK собираются
      одной командой. Проверка: `mise run generate`. Серверные артефакты
      генерируются, только если для фреймворка есть генератор; для Fastify его
      нет, сервер пишется по контракту вручную.
- [ ] Реализация совпадает с контрактом по путям, методам, полям, успешным
      ответам и ошибкам данных и конфликта. Проверка: API-тесты статусов и тел.
- [ ] Генерация повторяется в CI, а сгенерированные пути и запрет ручных правок
      записаны в `AGENTS.md`. Проверка: `check:generated` в общем прогоне.
- [ ] Фронтенд обращается к API только через сгенерированный SDK. Проверка:
      `fetch(` вне `web/src/client/` не встречается.
- [ ] Тесты покрывают основной сценарий бронирования и конфликт слотов, прогон
      в GitHub Actions зелёный. Проверка: `gh pr checks` на PR.
- [ ] Тест конфликта проверяет частичное наложение встреч разной длительности:
      60 минут в 10:00 и 30 минут в 10:30. Проверка: API-тест на смешанные
      длительности и отсутствие слота 10:30 у другого типа.
- [ ] Коммиты реализации ссылаются на тикеты, правило записано в `AGENTS.md` и
      проверяется commitlint. Проверка: прогон commitlint на диапазоне ветки.
- [ ] Тикеты реализованы через `/implement-spec`, результаты в одной ветке и
      прошли общее ревью.
- [ ] В тикете есть результат проверки теста с временно нарушенным правилом и
      подтверждение восстановления.
- [ ] release-please подключён и создаёт release-PR. Проверка: после пуша в
      `main` в открытых PR есть `chore(main): release …`.
