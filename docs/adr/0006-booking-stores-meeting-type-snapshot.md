# Бронь хранит снимок типа встречи

**Status**: accepted

**Дата**: 15 ноября 2026

## Context

Тип встречи можно редактировать и удалять без ограничений по броням: каталог
типов — это настройка, а бронь — обязательство перед гостем. Если бронь
ссылается на живой тип встречи, правка длительности задним числом переписала
бы уже согласованные встречи, а удаление типа сломало бы строки в кабинете
владельца или освободило занятое время. Одновременно типы встреч и брони
живут в памяти процесса и существуют только до перезапуска сервера.

## Decision

Бронь хранит снимок типа встречи на момент записи:

```
meetingType { id, name, durationMinutes }
```

- `name` и `durationMinutes` — значения на момент создания брони; правка или
  удаление типа их не меняют.
- `id` исходного типа сохраняется только для трассировки и не является живой
  ссылкой: тип может быть уже удалён.
- `description` в снимок не входит: гость и владелец видят её только в
  каталоге.
- `start` и `end` брони вычисляются и сохраняются при создании; `end` не
  пересчитывается при чтении.

Отменённая бронь сохраняет снимок и `start`/`end`, но не занимает слот и не
попадает в список предстоящих.

## Consequences

- Правка длительности типа не переписывает прошлые и предстоящие встречи;
  длительность конкретной встречи зафиксирована в её снимке.
- Удаление типа не отменяет брони и не освобождает время: занятость считается
  по сохранённым интервалам броней, а не по каталогу типов.
- Каталог и брони расходятся по данным: тип с тем же `id` может больше не
  существовать. Это ожидаемо и не требует восстановления.
- API отдаёт бронь с вложенным `meetingType` из снимка, поэтому клиенту не
  нужен отдельный запрос каталога, чтобы показать строку предстоящей встречи.
- Тесты проверяют, что правка и удаление типа не меняют бронь и занятость
  слота.

## Alternatives

- **Живая ссылка на тип встречи**: одна запись вместо копии, но удаление типа
  требует каскада или запрета, а правка длительности переписывает историю.
- **Снимок всех полей, включая описание**: полнее, но описание не участвует ни
  в правилах доступности, ни в строке предстоящей встречи, поэтому копия
  только увеличивает объём данных и расхождения.
- **Хранить только `durationMinutes` без `name`**: занятость сохранится, но
  владельцу нечего показать в строке брони после удаления типа.
