# Клиентский роутинг на react-router-dom

**Status**: accepted

## Context

Появляются две адресуемые страницы — главная `/` и запись `/book`; дальше
будут выбор слота и кабинет владельца. Приложение — SPA на Vite.

## Decision

Используем `react-router-dom`: `BrowserRouter` в точке входа, маршруты в
`App`, переходы — ссылками. Адреса читаемые: `/` и `/book`.

## Consequences

- У каждой страницы есть URL: ссылку на запись можно отправить, а обновление
  страницы не теряет место.
- В dev и preview Vite отдаёт `index.html` для клиентских маршрутов; при другом
  хостинге понадобится SPA-fallback.
- Тесты страниц оборачиваются в `MemoryRouter`, а роутер становится частью
  фронтенд-стека и его зависимостей.

## Alternatives

- **Переключение компонентов по состоянию без URL**: меньше зависимостей, но
  нельзя дать ссылку на запись и обновить страницу без потери места.
- **Файловый роутинг** (TanStack Router): мощнее, но для двух страниц избыточен.
