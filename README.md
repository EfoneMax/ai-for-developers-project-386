# Календарь звонков

Сервис бронирования встреч по мотивам [Cal.com](https://cal.com). Владелец календаря публикует доступное время, а гость без регистрации выбирает свободный слот и записывается на звонок.

Учебный проект Хекслета: https://ru.hexlet.io/programs/ai-for-developers  
Как это должно работать: https://files.hexlet.app/a/2ipc5m

## Сценарий гостя и владельца

### Владелец

1. Открывает кабинет владельца.
2. Создаёт тип встречи: название, описание и длительность.
3. Тип сразу появляется на публичной странице.
4. В разделе предстоящих встреч видит все записи гостей: дату, время, тип встречи и контактные данные гостя.
5. При необходимости отменяет предстоящую встречу: запись исчезает из списка, а слот снова становится свободным.

### Гость

1. Открывает публичную страницу без регистрации.
2. Выбирает тип встречи.
3. Открывает календарь на 14 дней и выбирает свободную дату и время.
4. Указывает имя, email и при необходимости комментарий.
5. Подтверждает запись.
6. Запись сразу появляется в списке предстоящих встреч владельца, а слот становится занятым.

## Сценарий в Cal.com (референс)

1. Войти в Cal.com и открыть раздел **Event Types** (в актуальном интерфейсе — **Links**).
2. Нажать **New → Event Type**, указать название, описание и длительность, например 20 минут. Сохранить тип встречи.
3. Открыть публичную страницу владельца (`cal.com/<username>`) и выбрать созданное событие.
4. Выбрать дату в календаре и свободное время, нажать **Continue**.
5. Заполнить имя и email гостя, при необходимости добавить заметку, и подтвердить бронирование.
6. Вернуться в кабинет → **Bookings → Upcoming**. Новая запись появится в списке владельца с датой, временем, типом встречи и данными гостя.

> Сценарий проверен на тестовом аккаунте Cal.com: новый тип встречи создан через **New → For myself**, после записи на него бронь появилась в **Bookings → Upcoming**. Для гостевой почты лучше использовать адрес, который реально принимает письма: на одноразовый домен Cal.com может не сохранить бронирование.

## Правила календаря

- Часовой пояс владельца: `Europe/Moscow` (UTC+3).
- Рабочие дни: понедельник–пятница, 09:00–18:00.
- Шаг доступных стартов: 30 минут.
- Окно записи: 14 календарных дней, начиная с сегодняшнего.
- Длительность слота равна длительности выбранного типа встречи.
- Пересечения запрещены, включая частичные и между разными типами встреч.
- Встречи встык разрешены: следующая может начаться в момент окончания предыдущей.
- Одновременные запросы на один слот обрабатываются атомарно.

## Стек и контракт

- **Контракт:** TypeSpec → OpenAPI.
- **Клиентский SDK:** генерируется из OpenAPI для TypeScript-фронтенда.
- **Бэкенд:** Node.js, TypeScript, Fastify. Маршруты реализуются по контракту и проверяются тестами.
- **Фронтенд:** React, Vite, TypeScript, shadcn/ui.
- **Тесты:** Vitest, включая дымовой тест запуска приложения.
- **Хранение:** в памяти процесса; после перезапуска сервера записи и типы встреч сбрасываются.

## Запуск и проверки

```bash
mise run setup   # зависимости, OpenAPI и SDK, Git-хуки
mise run dev     # API и фронтенд как daemons
mise run check   # линтеры, типы, тесты и сборка — то же, что в CI
```

API — `http://localhost:3000`, фронтенд — `http://localhost:5173`.
Остановить фоновые сервисы: `mise daemons stop`.
CI запускается на push в `main` и на pull request.

## Ограничения

- Нет авторизации и личных кабинетов: владелец один и задан заранее.
- Нет интеграций с внешними календарями и уведомлений.
- Нет переноса записи: отменить предстоящую встречу может только владелец.
- Владелец видит время в часовом поясе `Europe/Moscow`, гость — в своём часовом поясе.

## Реализация

В `main` находится каркас приложения: контракт TypeSpec, сервер Fastify, фронтенд на React и Vite, тесты и общая команда проверок. Главная страница с рассказом о сервисе и переходом на запись реализована; страница записи `/book` пока заглушка.
